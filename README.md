## 📘 詳細產品規格說明書 (System Specification)

### 一、 專案發想初衷與真實使用者痛點 (Origin & User Story)

#### 1. 為人本教育現場痛點而生
本專案的發想源自我的母親——她是一位資深的國中老師（同時兼任班級導師與數學科任教學）。在真實的國中教學現場，老師每學期都必須結算學生的「平時成績」並給予具體客觀的評語。然而，傳統現場常面臨三大極端痛點：
- **課堂手忙腳亂**：一手拿粉筆/課本、一手拿平板或紙筆，若記點操作超過 2 個步驟，在緊湊的 45 分鐘課堂中根本無法落實。傳統 App 往往需要「點選班級 $\rightarrow$ 滑動找學生 $\rightarrow$ 點擊學生 $\rightarrow$ 進入子頁面 $\rightarrow$ 輸入分數 $\rightarrow$ 按儲存」，多達 6 步的操作導致老師完全放棄在課堂中使用。
- **評分憑印象、缺乏客觀事證**：學期末結算平時分數時，往往只能憑學期末最後兩週的模糊記憶打分，既不公平，也缺乏具體客觀的事證紀錄。
- **親師座談缺乏數據支撐**：遇到需要個別輔導的學生時，手邊缺乏長期歷程紀錄，難以向家長具體說明學生成績「從何時開始下滑」或「在哪些常規上需要加強」。

#### 2. 貼心客製化與美學設計理念
為了真正幫媽媽減輕教學負擔，我以 **Vibe Coding（自然語言引導 AI 編程）** 的方式逐步打造這套 Web App：
- **三麗鷗風格（Hello Kitty & 小雙星 🌸）**：考量到國中教學壓力繁重，特別以 Hello Kitty、小雙星、美樂蒂等溫馨粉嫩粉彩為主視覺，搭配可愛吉祥物與柔和圓角動效，希望能為媽媽在忙碌的課堂經營中帶來療癒好心情。
- **實力至上主義教室風格（COTE OAA 🏛️）**：為了滿足我個人的二次元熱情，額外打造《歡迎來到實力至上主義教室》（高度育成高等學校）高對比黑紅終端主題，具備學生綜合實力 OAA 評級與動漫彩蛋（收錄 35 位官方高解析角色立繪與日語語音彩蛋），實現一鍵無縫切換雙主題。

### 二、 產品定位與核心架構原則 (System Architecture)

- **產品名稱**：ClassQuant Lite（課堂量化點記板與班級經營互動平台）
- **產品型態**：Zero-Build 純前端單一 `index.html` 互動式 Web App（PWA 架構，支援 100% 離線執行）。
- **目標客群**：國高中與國小班級導師、各科科任教師、課堂經營者。
- **三大核心設計原則**：
  1. **零滑動 1~2 秒極速交互**：5 欄緊湊排列，全班 30~40 人座位一屏掌控，單擊即完成加扣分。
  2. **雙軌量化機制**：學業均分（考試成績）與品格常規（加扣分點數）獨立計算，互不混淆。
  3. **資料 100% 本地隱私保障**：數據僅存放於瀏覽器 LocalStorage，保障學生個資無外洩疑慮。

> ⚠️ **【作業評測範疇與載具驗證特別聲明】**  
> 本專案在最初發想與原型設計時，雖然為了母親的課堂需求在行動端人因操作上投入了大量心血（例如單手操作動線、緊湊排版概念等）；**但因本專案主要為課程作業呈現，本次作業的評分與展示範疇以「標準電腦桌機端瀏覽器（Desktop Browser，如 Chrome / Edge）」為主。手機行動端（Mobile）未包含在本次作業的正式驗收與跨載具實機驗證範疇之中**。建議評審老師與助教評閱時，請以**電腦桌機開啟**以獲得最穩定、最標準的互動排版與圖表體驗。

### 四、 數學演算法模型與資料結構定義 (Mathematical Models & Schemas)

#### 1. EWMA 指數加權移動平均演算法
為了過濾單次小考因題目難易度或偶發失常引起的劇烈震盪，系統採用 EWMA 演算法繪製學業趨勢曲線：
$$S_t = \alpha \cdot Y_t + (1 - \alpha) \cdot S_{t-1}$$
- 其中 $Y_t$ 為第 $t$ 次小考之原始得分，$S_t$ 為平滑後指標。
- 系統平滑係數設定為 $\alpha = 0.3$，使曲線既能對近期表現保持靈敏度，又能有效過濾短期雜訊，精準判定學生處於「穩定上升」、「高原停滯」還是「漸進下滑」。

#### 2. 學業 $\times$ 常規四象限動態分群演算法
系統以班級品格常規平均點數 $\mu_{char}$ 與學業小考平均分 $\mu_{acad}$ 作為動態分割軸，將全班劃分為四個象限：
1. **第一象限（拔尖進階組，$\Delta_{char} \ge \mu_{char}, \text{Score} \ge \mu_{acad}$）**：品學兼優，引導加深加廣學習與自主探究。
2. **第二象限（潛力未發揮組，$\Delta_{char} \ge \mu_{char}, \text{Score} < \mu_{acad}$）**：生活常規良好但學業遇瓶頸，提供學業弱點診斷與補救教學。
3. **第三象限（高危機關懷組，$\Delta_{char} < \mu_{char}, \text{Score} < \mu_{acad}$）**：雙向低落，優先啟動親師晤談與專案認輔。
4. **第四象限（努力待輔導組，$\Delta_{char} < \mu_{char}, \text{Score} \ge \mu_{acad}$）**：學業優秀但常規散漫，強化自律生活常規與同儕互動。

#### 3. 五數綜合箱形圖與離群值檢測
計算全班小考分數之五數綜合指標：最小值 ($Min$)、第一四分位數 ($Q_1$)、中位數 ($Median$)、第三四分位數 ($Q_3$)、最大值 ($Max$)。
- 四分位距：$IQR = Q_3 - Q_1$
- 離群值邊界：$[Q_1 - 1.5 \times IQR, \; Q_3 + 1.5 \times IQR]$
- 協助教師一眼識破成績「雙峰分化（M型社會化）」現象。

#### 4. $2\sigma$ 斷崖式下滑預警演算法
計算學生歷史成績之標準差 $\sigma = \sqrt{\frac{1}{N}\sum_{i=1}^{N}(x_i - \mu)^2}$。當最新小考分數低於 $(\mu - 2\sigma)$ 時，系統自動標記「斷崖下滑警示燈號」，防範隱性學習危機。

### 五、 人因工程與介面適配規範 (Ergonomics & Accessibility)

1. **緊湊 5 欄排版（原始人因構想）**：針對國中 30~35 人標準班級規劃 5 欄緊湊排版，讓全班座位一屏完整呈現，無需多餘滾動。（⚠️ *備註：雖然在初期原型發想時投入了大量行動端操作的巧思，但本次作業成果展示與評分範疇聚焦於「標準電腦桌機端（Desktop Browser）」，手機行動端之跨載具實機相容性未包含在本次作業的驗證範疇之中。*）
2. **`--app-font-scale` 大字體防擠壓保護架構**：實作全域字體縮放，配合 CSS `clamp()` 與防折行彈性佈局，在長者模式與大字體（1.2x ~ 1.4x）下依然保持所有座位卡、姓名、按鈕完好無截斷。
3. **三級語意化色彩標準 (3-Tier Semantic Palette)**：
   - 翡翠綠 (`emerald`)：正向加分 (`+`)、優秀、連線正常。
   - 玫瑰紅 (`rose`)：違規扣分 (`-`)、警告、斷崖下滑。
   - 石板藍/岩石灰 (`slate`/`blue`)：中性事記 (`0`)、常規、學業均值。
4. **非視覺多重感官反饋**：點記時觸發微震動（Vibration API）與網頁音效合成器，在喧鬧吵雜的教室中讓老師無需盯著螢幕即可確認操作成功。

### 六、 Vibe Coding 提示詞討論與 AI 反覆迭代歷程 (Vibe Coding Prompts & AI Evolution)

本專案完全透過自然語言提示詞與 AI 反覆對話、除錯與演進，真實迭代歷程如下：

#### 階段一：人機對話釐清需求與討論規格
- **人類提示詞**：「我想要幫我當國中老師的媽媽寫一個課堂記點網頁，她需要能點名、加扣分、算平時成績。但她一手要拿粉筆，操作不能太複雜，你能幫我規劃系統規格嗎？」
- **AI 建議與規格收斂**：
  - AI 建議採用「模擬教室座位矩陣」取代傳統長條清單，並提出「單擊極速記點」概念。
  - AI 建議將「小考成績」與「常規點數」拆分為雙軌獨立指標，避免把生活常規與學業混為一談。
  - 敲定使用純原生 HTML5/JS + LocalStorage 離線存儲架構，避免伺服器維護與個資問題。

#### 階段二：初版原型實作與痛點優化（多輪迭代）
- **迭代 1（名冊匯入體驗）**：
  - *問題*：媽媽手動一個個輸入 35 名學生名字太耗時。
  - *Vibe Coding 修正*：向 AI 提出「請設計一個容錯正規表達式，只要複製學校 Excel 的兩欄，貼上就能一秒自動拆解座號與姓名」，成功實現 1 秒批次匯入。
- **迭代 2（行動端版面防擠壓與字體縮放）**：
  - *問題*：在手機或投影機大字體設定下，座位卡文字會換行重疊被遮蔽。
  - *Vibe Coding 修正*：與 AI 協同設計 `--app-font-scale` 彈性字體縮放機制，並使用 CSS `clamp()` 與 `flex-shrink: 0` 確保所有重要按鈕與姓名永不截斷。
- **迭代 3（投影機暗黑模式高對比度調校）**：
  - *問題*：切換到 COTE 暗黑主題時，教室老舊投影機對比度不足，扣分紅色文字看不清。
  - *Vibe Coding 修正*：重新定義語意化三級色彩規範（翡翠綠 `+`、高對比玫瑰紅 `-`、岩石藍 `0`），大幅提升可讀性。
- **迭代 4（統計戰情室深度視覺化接入）**：
  - *問題*：單純看點數總和無法識別學生需要哪種輔導。
  - *Vibe Coding 修正*：引導 AI 引入 Chart.js，實作「學業 $\times$ 常規四象限圖」與「EWMA 平滑趨勢圖」，建立具備教育心理學價值的科學分群。
- **迭代 5（單一 index.html 檔案收斂）**：
  - *問題*：作業嚴格規定整理成單一 `index.html` 檔案，需將多個獨立 CSS 與 JS 檔案整合成單檔。
  - *Vibe Coding 修正*：透過字串重構腳本，將所有 CSS 與 JS 無損編譯內嵌至 `index.html`，並修正正則轉義問題，成功交付零依賴單檔版本！

#### 階段三：自動排查 Bug 與單檔穩定性加固
- **迭代 6（班級名冊分頁報錯修復）**：
  - *問題*：切換至班級名冊分頁時出現空白，控制台報錯 `TypeError: this.store.getEventsByClass is not a function`。
  - *Vibe Coding 修正*：AI 自主啟動無頭瀏覽器與日誌診斷，發現 Store 類別方法命名不一致。在 Store 中補齊別名方法並在 `rosterManager.js` 加入防禦性呼叫，經自動化測試驗證全站 10 大分頁全部通過無報錯。
- **迭代 7（新手教學防干擾優雅降級）**：
  - *問題*：新手教學遮罩在不同手機尺寸偶發定位偏移。
  - *Vibe Coding 修正*：依使用者指示安全移除新手教學模組，簡化單檔體積並解除遮罩干擾。

3. **美學與實用性的共存**：既保留了三麗鷗為母親帶來的療癒溫度，又融入了個人熱愛的二次元終端美學，讓原本枯燥的成績管理工具轉化為富有人文關懷與互動樂趣的現代化 Web App。
